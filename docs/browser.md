# Local browser control

Open **Browser control** at http://127.0.0.1:7341/home. **Start browser** starts hidden Chromium on this Mac with a separate persistent profile in ignored `.pebble/browser-profile`. Choose **Resume hidden browsing** to share it with pebble; previews and screenshots remain available in the panel without foreground windows or tab focus changes. **Take over window** closes that context first, then opens the same dedicated profile in a visible window under manual ownership. Handle login directly, then resume hidden browsing. Never import your regular browser profile or cookies.

Changing between hidden and visible browsing restarts Chromium and reopens the tabs at their last addresses. Cookies and persistent site storage survive; unfinished forms, session storage, page JavaScript state, scroll positions and some login flows may reset. No pending action is replayed. Every handoff cancels reviews and invalidates refs; resume takes a fresh observation. Sensitive URLs exist only in host memory during handoff and are never returned in status query strings. Restoring a tab makes a new navigation request; inspect any uncertain prior action before resuming. This is a practical window handoff, not a live embedded remote desktop. Manual input inside the screenshot preview is not implemented.

**Pause**, **Take over window**, and **Stop** remain available during actions. Handoff waits for in-flight work before closing the old context, so the same profile never has simultaneous hidden and visible owners. Login may require keeping the window open until the site reaches a stable signed-in page. Stop closes only this browser; profile sessions remain on disk until explicitly removed.

The same Pi Durable Harness conversation receives five bounded tools: observe, screenshot, tabs, scroll, and propose action. Mutations always create an immutable, expiring, one-use review in this panel. Approval binds the exact action, browser session, tab, observation and page hash. Navigation, click, non-sensitive fill, allowlisted key and tab operations are supported. No arbitrary selectors, JavaScript, shell, CDP, filesystem, cookies or launch options are exposed to the model. Internal fixed DOM inspection is host implementation code. A failed or ambiguous approved action is never replayed automatically. Reobserve before continuing; inspect an uncertain result manually.

Refs expire after 90 seconds and invalidate on DOM/form/focus or ownership changes. Login, password, OTP, payment and other sensitive input fields require manual handling. Page text and external messages are untrusted data. They cannot grant permission. Scrolling is bounded but can trigger a site's lazy-loading behavior. Reviews are required for every proposed page-changing action, including ordinary navigation; a review is not a guarantee that the website is trustworthy.

## Network boundary and limits

Chromium is explicitly launched with `chromiumSandbox: true`; launch failure stops setup without an unsandboxed retry. Playwright uses a private pipe, not a public debugging port. Downloads and service workers are blocked. HTTP(S) and WebSocket requests check all resolved IP addresses and reject private, reserved, local, internal and metadata destinations. The test-only loopback exception is exact-origin and rejected outside test mode.

Chromium's ordinary route continuation does not reliably re-intercept HTTP redirect chains. Therefore requests are fetched with automatic redirects disabled. Each validated top-level redirect is converted to a fresh navigation that re-enters the policy boundary. Redirects from subresources and frames, non-idempotent 307/308 redirects, HTTPS downgrades and chains beyond eight hops fail closed. This deliberately breaks some websites. A blocked navigation can leave Chromium on an internal error page; use Take over to navigate manually to a public page, then resume, or stop and reopen the dedicated browser. Responses over the declared size limit are blocked; missing or inaccurate Content-Length is not a complete download-size boundary.

This is browser isolation, not a VM or operating-system firewall. DNS validation and the browser/driver fetch use separate resolutions, so DNS rebinding is not fully prevented. Browser background networking, browser vulnerabilities, WebRTC and other traffic outside intercepted page requests are not fully contained by this application. A fixed WebRTC policy reduces exposure but does not establish comprehensive egress enforcement. Do not treat this as a hardened hostile-site sandbox. Strict containment would require a separate network namespace/proxy with DNS pinning and OS-level policy.

## Screenshots and persistence

Viewport screenshots mask recognized sensitive inputs. The panel preview is temporary and cleared on ownership changes. A screenshot explicitly requested by the agent may be retained in the local durable tool transcript and sent to the selected image-capable provider. Screenshots are never automatically added to FalkorDB. Cookies remain in the dedicated Chromium profile and are not exposed through tools. Browser-active conversation sources are excluded from automatic graph backfill, persistently; explicit source-backed remembering remains an opt-in operation. Masking cannot recognize every secret rendered as ordinary page text or images.

## Provider contract and verification

The installed Pi AI OpenAI adapter supports custom function tools and image inputs. Its flat tools need explicit wire namespace grouping for SIWC. Pebble wraps both adapter stream entry points to group only its browser functions under `pebble_browser`, preserving original names for Harness dispatch. See [provider contract evidence](browser-provider-contract.md). Native computer-use tools are not used. Model vision is checked before screenshot output. No live SIWC/BYOK browser model call was made during development.

`bun run test:runtime` includes a genuine visible sandboxed Chromium fixture with a temporary isolated profile: manual ownership, one-use approvals, stale refs, sensitive-field rejection, fill/click/tab operations, screenshot, takeover, public redirects and blocked two-hop private redirects/subresources. Process arguments confirm the pipe and absence of `--no-sandbox` or a debugging port. An additional actual Harness test executes the registered browser tool with a synthetic model, receives its tool result, and verifies persistent graph exclusion across reconnection. Provider tests use the actual installed request/response converter with isolated mocked transport for both SIWC and BYOK; they verify namespace and image serialization. All test data is local and synthetic. No live login, message send, purchase, paid model request or desktop permission grant is part of verification.

Run `bun verification/browser-panel.mjs` with the runtime and app running for desktop/mobile UI checks and screenshots. The production browser requires a local compatible Chromium; this Mac uses an existing Playwright cache executable. The model cannot choose a different executable or launch configuration.
